## MODIFIED Requirements

### Requirement: 错误码分段

系统 SHALL 用**响应体 `code`** 表达业务结果，码值为 HTTP 风格数字 + 少量业务细分码：
`400` 参数/输入错误、`401` 未登录、`403` 无权限、`404` 资源不存在、`409` 冲突、
`429` 限流或配额耗尽（附 `data.retryAfterSec`）、`500` 服务端错误、
`503` 依赖不可用（配额服务不可用）、`4001` 内容护栏 L3 阻断、`4003` 容量排队、
`4004` / `4005` 未成年人宵禁 / 超限、`5000` 上游全链路失败。

> ⛔ 历史 `docs/05` 里的 `B1xxx / B2xxx / B3xxx / B5xxx / E5000` 分段**从未在代码中实现**
> （全仓 0 命中，2026-11-01 实测）。它只存在于文档里，因此 MUST NOT 作为对外契约或验收判据；
> 调用方按上表数字码处理。

#### Scenario: 跨用户越权

- **WHEN** 用户 A 用用户 B 的会话 ID 请求资源
- **THEN** 返回 `code=403`（旧文档写作 `B2002`，该码从未实现）

#### Scenario: 上游全链路失败

- **WHEN** 主链与所有降级级都失败
- **THEN** 返回 `code=5000`（旧文档写作 `E5000`），不伪造答案

#### Scenario: 配额耗尽

- **WHEN** 用户当日调用次数用尽
- **THEN** 返回 `code=429`，`data.reason="daily"`，`data.retryAfterSec` 为距次日 0 点的秒数
