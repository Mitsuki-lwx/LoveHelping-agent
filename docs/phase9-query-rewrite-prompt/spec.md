# phase9 · 方案与实测

> 状态：已交付（2026-09-21）。**`enabled` 默认值未改**（仍是 `false`）。

## S1 为什么以前量不准

改写挂在 `RetrievalAugmentationAdvisor` 的 **pre-retrieval** 阶段；而检索评测用的
`/admin/rag/retrieve` **直接调 `documentRetriever`、绕过 advisor**。
所以"改写对检索的影响"从来没进过评测口径 —— 2026-09-04 那条"改写劣化严重"的结论
只能靠聊天链路的日志嗅探，**既不可复现也不可对照**。

## S2 让它可测（对齐已有的 `rerank` 参数）

`/admin/rag/retrieve` 新增 `rewrite` 参数，复用**产线 `QueryRewriter`**（不另写一套），并回显：

- `effectiveQuery`：**实际送去检索的那串**（不是原始 query）
- `promptVersion`：本次生效的提示词版本

→ 从"看日志猜"变成"同一条请求里就能看到用了什么、命中了什么"，可归因。

单测守两条：`rewrite=false` 时 `verify(rewriter, never())`（一个字节都不改写）；
`rewrite=true` 时必须用改写结果检索、且原查询被完整保留（`startsWith` 断言）。

## S3 提示词：v1 的真实失效机理

v1（历史版，原样保留作对照）第 1 条是「**规范为简洁的**书面检索句」——"简洁"直接邀请**压缩**；
第 3 条只约束"不改变查询**意图**"，而意图不变 ≠ **实体**不变；
两个示例本身就在示范"丢原词 + 加新词"（例里「他冷战了我怎么办」的改写，原文的"我怎么办"没了，
"感情/沉默"是原文没有的）。**示例示范什么，模型就学什么。**

**实测（45 例，同后端同批次）**：

| 配置 | Recall@5 | MRR@5 | ΔMRR |
| --- | --- | --- | --- |
| 不改写（基线） | 0.93 | **0.807** | — |
| v1（旧提示词） | 0.89 | **0.704** | **−0.103（−12.8%）** |
| v2（约束版，第 1 轮） | **0.96** | 0.819 | +0.012 |
| v2（约束版，第 2 轮） | 0.93 | 0.807 | ±0.000 |

**v1 的样例把它自己出卖了**（`effectiveQuery` 实录）：

```
冷战筑墙怎么办  ->  感情 冷战 沉默 应对 修复 沟通          ← "筑墙"丢了
他不理我了咋办  ->  感情 冷战 沉默 如何应对 修复 沟通      ← 原词全丢，且与上一条塌缩成同一句
```

第 2 行是关键：**两个语义完全不同的查询被改写成了几乎同一句话**。
这不是"改写有点差"，是**查询塌缩**——检索自然比不上原查询。−0.103 的劣化因此有明确机理。

## S4 v2 修掉了塌缩，但**没有可证实的增益**

v2 的约束：**只许追加、不许改写或删减**；禁止引入原查询里没有的人名/书名/数字或另起话题；
拿不准就原样输出。实测样例：

```
冷战筑墙怎么办  ->  冷战筑墙怎么办 冷暴力 沉默 如何化解 破冰 沟通技巧 对话策略
他不理我了咋办  ->  他不理我了怎么办 冷漠 忽视 如何应对 沟通解决
煤气灯效应怎么办 ->  煤气灯效应怎么办 煤气灯操纵 情感操控 如何应对 恢复自信 心理咨询 建立界限
```

实体保住了、塌缩消失了。**但**：

1. **两轮之间自己就差 0.012**（0.819 / 0.807），而"增益"恰好也是 0.012 → **落在噪声内**。
2. 用例级（第 2 轮）：**变好 4、变差 2、不变 39**，净位移 ≈ 0。
3. v2 **没有 100% 遵守约束**：把"咋办"规范化成了"怎么办"（规则 1 要求逐字保留）—— 见 §S6。

**结论（按实测下，不按"提示词看起来更严"下）**：
**修提示词的价值是"拆掉一个陷阱"，不是"获得一个增益"。**
v1 是明确的坑（−12.8%，远超噪声带）；v2 把它填平了，但相对基线没有可证实的正收益。
→ 因此**保持 `enabled=false`**；默认提示词用 v2，避免将来谁打开就踩 v1 的坑。

## S5 本轮最重要的副产品：**带 LLM 的组件，单轮 45 例测不出小效应**

改写是一次 LLM 调用（非确定性）。同一配置两轮 MRR 差 0.012，
而 45 例上 0.012 的总位移不到"一个用例挪一个名次"。
**这意味着**：任何走 LLM 的组件（改写、rerank、路由判定）用**单轮 45 例对照**去测小效应，
都在噪声里；能测出来的只有 v1 那种 10% 量级的大效应。

要判"值不值得开"，得先解决非确定性：**多轮取中位 / 固定 temperature=0 / 扩样本**。
这条对项目里**所有**评测都成立，建议单独立项。

## S6 未验证 / 局限

1. **v2 未严格遵守"逐字保留"**（"咋办"→"怎么办"）；约束被部分遵守，不是硬保证。
2. **45 例单轮**，且改写非确定性 → v2 的增益无法判定；v1 的劣化可以判定。
3. **只改了 `QueryRewriter` 的提示词**，未改其触发条件（英文/非中文仍跳过改写）。
4. **`application.yml` 未加 `prompt-version` 占位符**（该文件正被另一条会话改动）→
   目前只能用 `-Dapp.rag.query-rewrite.prompt-version=v1|v2` 切换；env 覆盖待文件合并后补。
5. 未验证：改写对**多轮对话**（带上下文/代词）的影响；未测改写的延迟与成本。
