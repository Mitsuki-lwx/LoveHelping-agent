# 04 · 数据模型设计

## 1. 现状（As-Is，MySQL `agentdb`，schema.sql 自动执行）

现有表：`users`（含 tenant_id）、`user_conversations`、`message`（Phase 2 对话历史真源，取代原 `SPRING_AI_CHAT_MEMORY`）、`knowledge_entry`、`knowledge_vote`、`evolution_skill`（含 tenant_id + is_active）。

**问题**：
- `spring.sql.init.mode=always` + schema.sql —— 无版本化迁移，多环境必然漂移 → **改用 Flyway**（路线图 Phase 1）。
- ~~消息与 Spring AI 记忆表耦合，缺业务字段（软删、feedback、token 计量）~~ → **Phase 2 已落 message 表解决**（软删/feedback/prompt_version）。
- 无 Agent 任务表、无护栏事件表、无 Prompt 版本表。

## 2. 目标表设计（To-Be）

### 2.1 `conversation`（会话）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 雪花 ID |
| tenant_id | VARCHAR(32) NOT NULL | 索引 |
| user_id | BIGINT NOT NULL | 复合索引 (user_id, last_message_at) |
| mode | VARCHAR(16) | `CHAT` / `AGENT`（沙盘为远期附录，SRS §6 立项后加 `SANDBOX`） |
| title | VARCHAR(128) | 首条消息 LLM 摘要，异步生成 |
| status | VARCHAR(16) | ACTIVE / ARCHIVED / DELETED（软删） |
| token_usage | BIGINT DEFAULT 0 | 累计，成本核算 |
| last_message_at | DATETIME | 索引 |
| created_at / updated_at | DATETIME | 审计 |

### 2.2 `message`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| conversation_id | VARCHAR(100) NOT NULL | 复合索引 (conversation_id, created_at) |
| user_id | VARCHAR(50) | 归属审计（可能 anonymous，归属以会话为准） |
| role | VARCHAR(16) | USER / ASSISTANT / SYSTEM / TOOL |
| content | TEXT | **Phase 2 明文工作列**；Phase 3 ADR-4 加密后迁移为 content_encrypted |
| content_encrypted | VARBINARY | AES-256-GCM，密钥按租户派生（ADR-4，Phase 3） |
| content_hmac | CHAR(64) | HMAC-SHA256，幂等去重 + 日志追踪（V6 已预置列） |
| feedback | VARCHAR(8) | NONE / LIKE / DISLIKE（冗余，免连表） |
| prompt_version | VARCHAR(16) | 归因用（见 08 §2.4） |
| deleted | TINYINT | 软删标记（0/1，ADR-5 配定时物理清除） |
| created_at | DATETIME | 索引 |

> **Phase 2 落地说明（2026-08-19，Flyway V6）**：当前实现以 `content` 明文承载对话内容（Phase 2 无加密能力），
> `content_hmac` 列已预置。整体加密按 ADR-4 于 Phase 3 做两段式迁移（加 content_encrypted → 双写 → 切读 → 删 content，见 §5），
> 期间 feedback/prompt_version/软删等业务能力已可用。`message` 已成为对话历史真源，`SPRING_AI_CHAT_MEMORY` 废弃。

### 2.3 `agent_task`（ADR-3）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 对外 taskId |
| tenant_id / user_id | BIGINT | |
| instruction | TEXT | 原始指令 |
| status | VARCHAR(16) | PENDING/RUNNING/SUCCESS/FAILED/CANCELLED，乐观锁 version 列 |
| result_ref | VARCHAR(255) | 结果产物（PDF 等）的对象存储 key |
| error_code / error_msg | VARCHAR | 失败归因 |
| token_usage | BIGINT | |

| idempotency_key | VARCHAR(64) | 唯一索引，防重复提交 |

### 2.4 `guardrail_event`（护栏审计）

`id, tenant_id, user_id, level(L1/L2/L3), rule_id, content_hmac, action, created_at`。
**永不存原文**，只存 HMAC 与命中规则 ID —— 这是误报率监控（ADR-6）的数据源。

### 2.5 现有表改造

- `evolution_skill`：加 `audit_status(PENDING/APPROVED/REJECTED)`（自动萃取默认 PENDING，审核通过才可被检索，向量化前移审核）+ `vector_id`（pgvector 行关联）。
- `users`：删除任何明文敏感字段；加 `status`（ACTIVE/DISABLED/DELETED）支撑注销级联（ADR-5）。
- `knowledge_entry` / `knowledge_vote`：保持，补齐租户索引。

### 2.6 向量库（pgvector，ADR-1，Phase 1 已收敛）

单表 `vector_store`（Spring AI pgvector starter 自动建表）：`id, content, metadata(jsonb), embedding vector(1024)`。
- 知识文档（`document/` 下的 MD）与进化 Skill 均写入该表，`metadata.source` 区分来源（`doc` / `evolution`）。
- 租户过滤：单租户期知识库为全站共享（ADR-13），暂不按 tenant 过滤；多租户重启后升级为强制检索条件。
- 检索统一走 `HybridRetrievalService` 门面（相似度检索），Milvus/ES 混合检索已移除。

### 2.7 `message_media`（图片附件，ADR-11）

### 2.8 `user_memory`（结构化事实记忆，ADR-14，阶段 2 落地）

### 2.9 `conversation_summary`（会话摘要，ADR-14，阶段 2 落地）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| conversation_id | VARCHAR(100) PK | 与 user_conversations 关联 |
| user_id | BIGINT NOT NULL | 归属校验 |
| summary | TEXT | LLM 压缩摘要（脱敏，含结论/待办/情绪状态） |
| summary_version | INT | 每次压缩递增，同一条 conversation 覆盖更新 |
| last_summarized_at | DATETIME | 触发增量压缩依据 |

### 2.10 `relationship_profile`（关系档案，ADR-14，阶段 3 落地——**远期附录**，依赖沙盘/诊断立项，SRS §6）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| user_id | BIGINT PK | 与 users 1:1 |
| stage | VARCHAR(32) | 关系阶段（暧昧/热恋/磨合/异地/分手修复…），诊断结果可回填 |
| key_people | JSON | 关键人物（昵称+角色），脱敏 |
| preference_conflicts | JSON | 已识别的偏好冲突点（注入时重点提示） |
| alerts | JSON | 预警事项（如"提及自伤倾向"→ 转介） |
| last_updated_at | DATETIME | 每次萃取后更新 |

**存储边界（ADR-14 红线）**：以上所有表只存**脱敏后的事实/摘要**，私信原文只在 `message`（加密）与 ChatMemory 窗口。语义记忆（阶段 3）只向量化摘要与已审核 Skill，原始私信永不向量化。

> **待立项数据需求（SRS §3.2，FR-CORE-01/02）**：话术三级建议与情绪刹车片的数据模型在立项时补充（可能复用 `guardrail_rule`/`guardrail_event` 体系——**实现方式待讨论**，当前不设计）。

## 3. Redis Key 规范

> 边界：Redis 是易失缓存，**不做记忆/登录会话的真源**——事实记忆以 MySQL、语义记忆以 pgvector 为真源（ADR-14）。Redis 只承担：热缓存、计数器、幂等/防重、登录态辅助。

| Key | 类型 | TTL | 用途 |
| --- | --- | --- | --- |
| `ratelimit:user:{userId}:{yyyyMMdd}` | String 计数 | 当日 | 用户日配额（启用现有 RateLimiter，对象由租户改为用户，ADR-13） |
| `auth:blacklist:{jti}` | String | token 剩余有效期 | JWT 登出/改密后黑名单，支持强制下线（JWT 本身无状态） |
| `auth:fail:{username}` | String 计数 | 10min | 登录失败计数（防暴力） |
| `chat:ctx:{conversationId}` | Hash | 1h | 热会话上下文缓存（最近 N 轮），MySQL 为真源（可选优化，当前窗口直读 message 表） |
| `mem:inject:{userId}` | Hash | 5min | 用户档案/活跃事实注入结果缓存，避免每轮重复查 user_memory |
| `mem:extract:{conversationId}` | String | 1h | 会话记忆萃取防重标记（幂等） |
| `agent:task:notify:{taskId}` | Pub/Sub | - | Agent 完成通知（SSE 推送触发） |
| `idempotency:{key}` | String | 10min | 提交幂等 |
| ~~`llm:cache:*`~~ | - | - | **删除**（ADR-7） |
| ~~`sandbox:*`~~ | - | - | 沙盘为远期附录（SRS §6），立项时历史必须异步落库，Redis 仅热缓存 |

**规范**：所有 key 必须带业务归属维度（当前为用户级，ADR-13）；禁止用无前缀裸 key。tenant_id 列在各表中保留并固定 `default`（tenant-ready），不改表结构。

## 4. 数据生命周期

| 数据 | 保留策略 | 删除动作 |
| --- | --- | --- |
| 会话/消息 | 用户可见期内保留；注销后软删 30 天 | 定时任务物理删除 + 级联删向量/Skill（ADR-5） |
| 图片附件 | 随所属消息；注销级联同消息 | 删消息即删对象存储文件（07 §6） |
| guardrail_event | 180 天 | 滚动清理 |
| agent_task | 90 天 | 滚动清理（结果产物同步删对象存储） |
| Spring AI chat memory 表 | 并入 message 后废弃 | 迁移完成即 drop |

## 5. 迁移纪律

- 所有 DDL 进 Flyway（`V{n}__desc.sql`），禁止 schema.sql 自动执行。
- 破坏性变更（删列/改类型）必须两段式：加新列 → 双写观察 → 切读 → 删旧列。
