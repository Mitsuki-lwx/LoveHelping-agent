# 用 Jev 替换情绪打分 —— 任务拆分（tasks）

> 立档 2026-09-20。用户指令：「用 Jev 换有提升的地方」。上游：`docs/phase7-jev-routing/`（探针）。

## 1. 为什么选这一处（不是为省钱）

`SentimentService` 现在这样做：**用生成模型输出 `[SCORE]…[/SCORE]` / `[WHY]…[/WHY]`，
再用正则从自由文本里抠出数字**：

```java
private static final Pattern SCORE_P = Pattern.compile("\\[SCORE\\]\\s*(-?[0-2])\\s*\\[/SCORE\\]");
```

对照官方文档（`/primitives`、`/concepts/how-to-build-with-system-one`）的定位——
"**代码拥有流程，AI 只做窄的、结构化判定**"、"**答案永远被约束在你给的选项里，代码不需要从生成的散文里取值**"——
情绪打分（-2~2 五档）恰好是一个 `Score` 问题：**它是判定，不是生成**。

提升点：

| 维度 | 现在 | 换成 Jev `Score` 后 |
| --- | --- | --- |
| 取值可靠性 | 正则抠自由文本，格式跑偏就静默得 0 分 | 取值**被约束在五个档位内**，不可能是档位外的值 |
| 失败可见性 | 格式错 → 静默 0，**看起来像"用户很平静"** | 失败即失败（不写记录），不会伪装成"平静" |
| 延迟 | 一次生成模型调用 | p50 ≈0.7s（探针实测） |
| 成本 | 生成模型 token | 小得多的分类调用 |
| 一致性 | 受 prompt 漂移影响 | 同一档位描述恒定 |

**代价（如实说）**：丢掉"一句话说明为什么"的自由文本原因，改为存**档位描述**（规范中文，如"低落、难过、沮丧"）。
若将来确实需要个性化理由，再考虑多问一个 `choice` 选原因类别，而不是让模型写句子。

## 2. 目标

1. 用 Jev `Score`（5 档）替换 `scoreText` / `scoreConversation` 里的生成调用，
   **DB 语义不变**（仍是 `-2..2` 的整数分 + `reason` 文本）。
2. 保留**原有 LLM 路径作为回退**：Jev 未启用/不可用/超时 → 走原路径，
   保证"情绪线是增强不是硬依赖"这个既有性质不被破坏。
3. 可配置、可关闭，密钥**只走环境变量**（AGENTS.md §3）。
4. 用**带人工标签的用例**对比两条路径的准确率与延迟，证明"确实有提升"。

## 3. 非目标

- 不改 DB schema、不改 API 出参形状（`SentimentLog` 字段不动）。
- 不动 `CapabilityRouter` / 主对话链路 / 护栏。
- 不追求"用 Jev 降本"（`docs/phase7-jev-routing/spec.md` §S5 已论证本仓库降本空间在 embedding，不在这些点上）。

## 4. 边界

- 新增一个 HTTP 客户端与一处调用点；**不引入任何新 maven 依赖**（JDK `HttpClient` 即可）。
- 超时**必须短**（后台增强，不许拖慢请求）；失败**不得抛到调用方**（保持既有的静默降级风格）。
- DoD：编译 + 单测 + 触达面 E2E（`POST /sentiment/score` → `GET /sentiment/timeline`）。
