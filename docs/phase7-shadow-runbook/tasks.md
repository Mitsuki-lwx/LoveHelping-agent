# phase7-shadow-runbook · 让「生产影子观测」可执行

> 承接 ADR-37 的收尾条件："**先在生产 shadow 上量出真实误报率，再用同一批流量重新标定阈值**"。
> 但上一轮结束时只有"开关能打开、事件会落库"，**没有操作手册、没有读数的工具、
> 而且审计表还漏记一类事件**。这轮把它补齐成"照着做就能拿到结论"的东西。

## 目标

1. **补审计缺口**：`ChatEntry` 的词典 L3 拦截此前只记 meters、不落 `guardrail_event`，
   导致 SQL 看不出"词典兜底拦了多少条"（上一轮 E2E 里 `BLOCKED 事件数 = 0` 即此）。
2. **给出读数工具**：`scripts/guardrail_shadow_report.py` —— 从 `guardrail_event` 出
   分布/越阈占比/失败计数，并能导出人工复核清单、回填标注后算**两个不同口径**的误报指标。
3. **写清判定门槛**：什么条件才允许把 `mode` 从 `shadow` 推到 `enforce`（三个数，缺一不可）。
4. **更正一处上一轮的错断言**："当前没有主动取消在途请求" —— 实测是错的。

## 边界

**做**：`ChatEntry` 补一行审计（+2 个单测 + 对照实验）；新增报告脚本；写 runbook。

**不做**：

- **不改阈值**。ADR-37 已说明负向集是我本人写的，改值必须等真实流量。
- 不改产品默认（`mode` 仍 `off`）。
- 不引入新的外部依赖，不动容量治理。

## 拆分

| # | 任务 | 产出 |
| --- | --- | --- |
| T1 | 三件套 + runbook | 本目录 |
| T2 | 审计补全（只补 L3，避免与 `GuardrailAdvisor` 的 LOGGED 双计） | `ChatEntry` + `ChatEntryTest` |
| T3 | 报告脚本（含 Wilson 区间、两个口径分离） | `scripts/guardrail_shadow_report.py` |
| T4 | 实测更正"超时是否中止请求" | `fake_jev.py` 加断开探测 + 5 处文档更正 |
| T5 | 回归 + 提交 | — |

## 风险

- **R1**：审计补全可能造成**双计**（同一条消息被 `ChatEntry` 与 `GuardrailAdvisor` 各记一次）。
  → 只在会被 `throw` 出去的 L3 分支补，L1/L2 不补（那条路径请求会继续走到 LLM，advisor 已记）。
- **R2**：报告脚本容易把两个口径混起来报（"越阈样本里的误报占比" ≠ "全量误报率"）。
  → 脚本把两者分开写，并在输出里直接写明"这不是全量误报率，还需要什么才能算"。
