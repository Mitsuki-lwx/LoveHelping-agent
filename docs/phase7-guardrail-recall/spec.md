# 护栏口语化危机加召回 —— 方案（spec）

## S1 问题设计

复用 `JevClient`，新增 `noul` 方法（官方 `noul` = 干净的是/否，概率本身即信号）：

```
question id: self_harm
type       : noul
instructions: "`user_text` 是否表达了自伤、自杀或「不想继续活下去」的意愿？
               包含口语化、隐晦、玩笑式的说法也算。纯粹的夸张修辞不算。"
criteria.true : 有自伤/自杀意愿或绝望到不想活的表达
criteria.false: 没有这类表达，或只是抱怨劳累、夸张修辞
```

**只问一个问题**：官方明确"一次请求里每个问题独立评估、加问题几乎不增加耗时"，
但护栏只需要这一个信号；多加问题只会增加 token 而没有任何消费方。

## S2 阈值与升级路径

| 规则层 | Jev 结果 | 行为 |
| --- | --- | --- |
| `level >= 3` | **不调用 Jev**（省一次网络往返） | 原样硬阻断（**一字不改**） |
| `level < 3` | 未启用 / 调用失败 | 原样（等于今天） |
| `level < 3` | `noul < min-probability` | 原样 |
| `level < 3` | `noul >= min-probability` | **升级为 L3 自伤处理**：返回同一份转介文案、记 `ruleId=jev:self_harm` |

- **接点（2026-09-20 实测修正）**：接在 **`ChatEntry.guardrailCheck`**，不是 `GuardrailAdvisor`。
  理由有二：① 实测证明 SSE 路径的输入拦截根本不经过那个 advisor（词典的拦截也来自 `ChatEntry`）；
  ② advisor 那层拿到的 user message 已掺入技能/检索注入，**同一句话的概率会被稀释**。
  接在 `ChatEntry` 还能保证拿到用户原话。advisor 上的钩子已撤除，避免每条消息被收两次钱。
- **为什么走同一份转介文案而不是新写一套**：词典对同类内容就是这个输出，两套文案会让
  "同样的危机表达因来源不同而体验不同"。复用 = 一致。
- **阈值 = 0.6，是标定出来的**：`scripts/jev_guardrail_threshold_probe.py` 在 12 例标注上实测，
  阈值 0.3~0.6 召回都是 8/8 且误报 0，0.7 掉到 6/8，**0.9 只剩 3/8**；
  正例最低 0.61、负例最高 0.05（分离度 12 倍）。最初拍 0.9 会白丢一半召回。


## S3 失败语义（必须如实写进文档与代码注释）

Jev 不可达/超时/非 200 → `Optional.empty()` → **不升级**，行为与今天完全一致。
**这不是"安全回退"**：今天本来就漏这些口语变体，只是没有变得更差。
真正的兜底仍然是词典规则——它**零延迟、确定性、不依赖网络**，这条性质本轮不动。

## S4 配置

```
app.jev.enabled                     # 总开关（已有，默认 false）
app.jev.guardrail.enabled           # 护栏加召回开关（默认 false）
app.jev.guardrail.min-probability   # 升级阈值（默认 0.9）
```

两个开关分开：情绪打分的替换与安全边界的变更**必须能独立开关**。

## S5 验证

1. **单测**（本地 `HttpServer` 桩）：
   - `JevClient.noul` 的请求体形状（id/type/criteria）与解析；
   - 阈值边界：`0.9` 升级、`0.89` 不升级；
   - 未启用 → **零 HTTP 调用**且不升级；
   - 超时/429/缺字段 → 不升级且**不抛异常**；
   - `GuardrailAdvisor`：规则命中 L3 时**不**调用 Jev（省调用），且输出仍是原文案。
2. **真实对照**（同一批人工标注消息，两次真实应用实例）：
   - Jev 护栏**关**：统计走转介文案的条数（= 词典的召回）；
   - Jev 护栏**开**：同批再测，统计转介条数 + **负向用例的误报数**；
   - 观测口径：SSE 回复是否包含 `全国心理援助热线`（转介文案的特征串）；
   - 额外量：开启后**每条消息的额外延迟**（这就是要交给产品判断的代价）。
3. **回归**：全量单测 + `e2e_live.py` 22 项。
