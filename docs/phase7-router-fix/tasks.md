# 路由规则的两处漏判 —— 修复（tasks）

> 立档 2026-09-20。上游：Jev 路由探针（`docs/phase7-jev-routing/`）对照实验里暴露的**产线真缺陷**，
> 不是 Jev 本身的问题。用户指令：「先修」。

## 1. 缺陷一：`needTools` 只在关键词出现在**前 6 字内**才命中

**根因（静态可读）**：`CapabilityRouter.hasToolIntent` 用

```java
message.matches("(?i).{0,5}(搜索|查一下|...|天气|...).{0,30}")
```

`String.matches()` 要求**全串匹配**，而模式以 `.{0,5}` 开头 → 关键词必须落在**第 0~5 个字符**内。

**实测后果**（28 例语料，`outputs/rule-router-*.json`）：

| 用例 | 期望 | 实际 |
| --- | --- | --- |
| 北京今天适合户外约会吗？查下天气 | agent | **normal** |
| 帮我搜一下附近适合第一次约会的咖啡馆 | agent | **normal** |
| 2025 年之后离婚冷静期有没有新的政策变化？帮我查证一下 | agent | **normal** |

即：**用户要实时信息时拿不到工具**（`classifyInner` → `R_NORMAL`）。同时关键词表本身也缺
`查下/搜一下/查证` 这类口语说法。

## 2. 缺陷二：`isAdviceRequest` 漏掉"求方法/说法"型请求

规则是刻意收窄的（注释写明"避开会被撞中的宽泛词"），但漏了两类：

| 用例 | 期望 | 实际 |
| --- | --- | --- |
| 消息老是已读不回，有什么办法能让他主动找我聊 | advice | normal |
| 刚认识一周，想约她出来，有什么自然的说法 | advice | normal |

用户要的是话术，却拿不到话术三级。

## 3. 目标

1. 修掉**位置约束**这个明确的实现缺陷（不是猜的政策）。
2. 补**口语说法**：`查下 / 搜一下 / 查证` 等，以及"求方法/说法"型话术请求。
3. **不引入新的误判**——尤其不能把情感叙述里的"天气""地图"误判成要查外部信息
   （误判成 Agent 的代价是**多轮 LLM 调用**，比漏判更贵）。
4. 用**带标签语料 + 单测 + 反向对照实验**证明"改了确实不一样、且没坏别的"。

## 4. 非目标

- 不动 `isOffTopic` / `isSimpleQuestion` 的既有判据（本轮无法证伪的改动不做）。
- **不引入 Jev 调用**进产线（那是下一步，需另立 ADR 与成本核算）。
- 不改路由**拓扑**（仍是那 5 条分支）。

## 5. 边界

- 只改 `CapabilityRouter` 一个类 + 其单测。
- 判据以**人工标签语料**为准（`scripts/jev_routing_cases.json` 的 28 例），不拿 Jev 输出当标准答案。
- DoD：编译 + 单测 + 触达面 E2E（聊天管道 → §7.2/7.3 冒烟）。
