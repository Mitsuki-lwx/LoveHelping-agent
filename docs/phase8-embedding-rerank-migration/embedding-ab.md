# embedding 干净对照实验（dashscope vs 硅基流动）

> 立项背景：Phase 8 清单与 `spec.md` §S7 里留着一条**未验证项** ——
> "0.807（迁移前 dashscope）→ 0.751（迁移后硅基流动）"，但这两数**口径不同**，不能据此断言"换 embedding 掉分"。
> 本文档补齐这个对照。

## 1. 要回答的问题

**把检索的 embedding 从 DashScope `text-embedding-v3` 换成硅基流动 `Qwen/Qwen3-Embedding-0.6B`，
检索质量是否变化？**

## 2. 为什么旧数据不能当答案（口径差异清单）

| 维度 | 0.807（迁移前） | 0.751（迁移后） | 是否混杂 |
|---|---|---|---|
| embedding 模型 | dashscope text-embedding-v3 | siliconflow Qwen3-Embedding-0.6B | ← **被研究的变量** |
| 代码版本 | phase9 时期 | phase8 时期 | ⛔ 混杂（RRF 参数/`top-k`/过滤逻辑都在演进） |
| 轮次 | **单轮** | 3 轮 | ⛔ 混杂 |
| rerank | 关 | 关 | 一致 |
| 测试集 | 45 例 | 45 例 | 一致 |

→ 差 0.056 里**混着代码版本差**，不能归给 embedding。

## 3. 设计（只变一个变量）

- **两臂**：
  - **A 臂（旧）**：`RAG_EMBEDDING_PROVIDER=dashscope` + 旁库（09-21 迁移前备份，dashscope 向量）
  - **B 臂（新）**：`RAG_EMBEDDING_PROVIDER=siliconflow` + 主库（当前，硅基流动向量）
- **两臂全同**：代码 HEAD `3f828cd`、评测脚本 `scripts/retrieval_eval.py`、45 例 ground truth、
  `--rerank` 不传（重排全关）、`QUERY_REWRITE_ENABLED=false`、同一个 PostgreSQL 实例、
  **同一天同一时段**、每臂 **3 轮**。
- **旁库**：`lwx_embed_cmp`，由 `vector_store_before_phase8.dump` 恢复（784 行 = 345 记忆 + 439 知识）。
  用 `APP_PGVECTOR_DATASOURCE_URL` 指过去，**主库全程不动**。

## 4. 判据（**先写死，事后不许改**）

- 主判据 Δ = MRR@5(B) − MRR@5(A)
  - |Δ| < **0.012**（phase9 实测噪声带）→ **无差异**，旧结论"换 embedding 掉分"**作废**
  - Δ ≤ −0.012 → 硅基流动**掉分**（掉多少按实测写）
  - Δ ≥ +0.012 → 硅基流动**更好**
- 副判据：Recall@5 同口径。
- 同臂三轮若**不相等** → 存在非确定性，先解释来源，**不得直接取均值**。

## 5. 前置断言（不满足就中止，不许硬跑）

- [ ] 旁库全表指纹 = `ab2d8535d038d3ef1112e639dca94876`（phase8 清单记录值）
- [ ] 两库**知识块**（`source not in ('memory','evolution')`）行数相等
- [ ] 两库知识块内容一致（抽取 `content` 的 SHA-256 后再比，避免"行数巧合相同"）
- [ ] 应用**确实连到了目标库**（查 `pg_stat_activity.datname`，不靠"我设了环境变量"）
- [ ] 应用启动日志回显的 embedding provider 与臂一致
- [ ] dashscope 通道实测可用（能返回 1024 维向量）

## 6. 已知混杂项（结论里必须声明）

1. 旁库 784 行 vs 主库更多行（记忆行增长）。若 §5 的两条"知识块一致"通过，
   且源过滤下推生效（ADR-43），则检索候选池两臂相同 → 记忆行数差**不影响**结论；
   若不通过，本实验**无效**。
2. 向量由不同模型生成 —— 这正是被研究的变量，不算混杂。
3. rerank 全关，只测"召回+排序"这一段（重排另案，见 ADR-41/42）。

## 7. 结果

### 7.0 先说一件计划外的事：本轮撞出一个 P0，实验被迫重跑

第一次跑完（A 0.824 / B 0.762）顺手打开重排复测，质量**崩到 0.28**。
查下去与重排无关 —— 是 **ADR-43 引入的载荷缺陷**：`KnowledgeSqlSearch.toDocument()` 用了
`Document(String, Map)`（实为 `(text, metadata)`），导致 **正文列被当成 id、id 变成随机 UUID**。
详见 **ADR-46**。

**所以第一次那组数（A 0.824 / B 0.762）是"缺陷态读数"，已作废**：

- id 随机 → 向量通道与关键词通道的同一块在 RRF 里配不上对 → 重复条目占候选位；
- 实测 `AdminController` 的 `hits=8` 平均只覆盖 **5.39 个不同文件** → 评测用的 `files[:5]`
  几乎等于"整份返回列表"，指标被**系统性抬高**（修复后为 5.91，才恢复"截断"语义）。

下表是**修复后**重跑的同一实验（同一天、同装置、同 45 例）。

### 7.1 主结果

| 配置 | Recall@5 | MRR@5 | 轮次 |
| --- | --- | --- | --- |
| **A 臂** dashscope 向量 + 无重排 | 0.89 | **0.704**（0.698 / 0.704 / 0.704） | 3 |
| **B 臂** 硅基流动向量 + 无重排 | 0.89 | **0.714** ×3 | 3 |
| **A 臂** dashscope 向量 + 远端 8B 重排 | 0.98 / 0.96 | **0.910**（0.913 / 0.907） | 2 |
| **B 臂** 硅基流动向量 + 远端 8B 重排 | 0.96 | **0.885** ×2 | 2 |

（A 臂第 1 轮 `n=44 skipped=1`：一条查询遇上 DashScope embedding 上游瞬时错误，第 2/3 轮恢复正常。）

### 7.2 按 §4 预写判据判定

| 比较 | Δ = B − A | 噪声带 0.012 | 判定 |
| --- | --- | --- | --- |
| **无重排 MRR** | **+0.010** | 带内 | **无差异** |
| 有重排 MRR | **−0.025**（dashscope 更好） | 带外 | 有利于回滚，但**只有 2 轮/臂 → 弱证据** |

**结论：**

1. **旧结论作废**。Phase 8 清单里「换 embedding 掉分」（0.807 → 0.751 / 或 spec 里的 0.8352）
   是**跨口径**比较（代码版本、轮次、候选窗都变过），且迁移后那个数还是**缺陷态**读数。
   **同口径重测：无重排下两种 embedding 没有可测差异（Δ=+0.010，带内）。**
2. **有重排时 dashscope 略好（+0.025）**，但证据强度**弱**（每臂仅 2 轮）。
   不足以支撑"回滚到 dashscope"—— 回滚要重嵌入全库，并放弃 OpenAI 兼容协议带来的供应商中立性。
3. **顺带校正一个正收益**：Phase 8 记录的「硅基流动 + 重排 = 0.856」，
   在修掉载荷缺陷后是 **0.885** → **该缺陷一直在压重排**（喂 UUID 打分）。

### 7.3 逐例配对（无重排，修复后）

无重排两臂逐例比较见 `outputs/embedab-*`：A/B 两臂三轮**各自逐字节相同**（本轮窗口内可复现），
说明修复后 B 臂的抖动没有复现（抖动率 ≈1/10，3 轮碰不到属正常）。

### 7.4 仪器标定（本实验的附带产出，值得单独记）

| 项 | 实测 |
| --- | --- |
| 同臂三轮可复现性 | 修复后 A/B 两臂三轮**逐字节相同** |
| **上游 embedding 确定性** | **不确定**：同一文本 10 次调用出 **2 种向量**，`cos≈0.99995`，抖动率 ≈ **1/10**（dashscope 侧 8/8 一致） |
| 抖动造成的翻转 | 修复前观测到 **2/45** 例在两种固定状态间翻转（top1↔top3、top5↔出局） |
| 仪器分辨率 | ≈ ±1 例 ≈ **±0.015 MRR**（比预写的噪声带 0.012 略宽） |
| 评测期库稳定性 | `APP_SCHEDULER_MASTER_ENABLED=false`，前后行数相等（784/784、964/964），调度器写入日志 0 条 |
| **索引重建影响** | 两库"走索引 top-8"vs"精确 top-8"平均重合 **1.000**、top-1 **50/50** → 排除 |

## 8. 未验证 / 局限

- ⚠️ **有重排两臂各只 2 轮**（无重排各 3 轮）→ Δ=+0.025 的置信度弱，只够写"倾向"。
- ⚠️ **仪器分辨率 ±0.015**：小于这个量级的差异本实验判不了（含"两 embedding 是否真等价"）。
- ⚠️ 两臂"三轮一致"只说明**在本次时间窗内**一致，不等于确定性（B 臂修复前就翻转过 2 例）。
- ❌ **未测硅基流动其他型号**（Qwen3-Embedding-4B/8B 是 2560/4096 维，换要连表一起重建）。
- ❌ **未做人工抽检**（只有聚合指标 + 逐例 MRR，没有"读一遍 top5 是不是真的相关"）。
- ❌ 未测真实聊天链路的**答案质量**（`answer_eval.py` 未跑）—— 本实验只到检索层。
- ⚠️ 旁库是 09-21 的备份，记忆行数 345 vs 主库 520：**知识块内容 SHA-256 完全一致**、
  且过滤已下推，故候选池相同（已断言）；但这仍是一条需要声明的差异。
