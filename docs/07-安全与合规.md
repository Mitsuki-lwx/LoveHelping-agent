## 4. Prompt 注入防护

| 载体 | 对策 |

## 5. 内容与心理合规（P0）

1. **免责声明**：产品级「AI 建议 ≠ 专业心理咨询」常驻展示（前端 + 首次会话 System 注入）。
2. **转介**：L3 触发自伤关键词时，回复附心理援助热线等资源；`guardrail_event` 级别为 L3 的触发次日人工复核。
   ⚠️ **输入侧与输出侧的判定条件不同（ADR-55，2026-09-28 起）**：
   - **输入侧**（用户原话）：`scope=INPUT`，**裸关键词即触发** → 用户表达自伤念头必须转介（"宁可严"）。
   - **输出侧**（助手回复）：`scope=OUTPUT`，**只在"建议/教唆"语境**（建议类词 + 自伤词同句相邻）才拦。
     ⛔ 理由：输出侧「你最近有没有想过伤害自己？」是**专业危机干预指导**，不是危险内容。
     修前用一套裸词表同时服务两侧 → 实测 3 组「如何帮助低落的朋友」的正常求助 **6/6 轮被误拦**
     （知识库里有《自伤与自杀风险：如何回应并求助》，助手引用时必然带出这些词）。
   ⛔ **已知限制**：用户**转述**他人的自伤词（"朋友说他想自杀"）仍会被**输入侧**拦掉 →
     答非所问。这是"宁可严"的代价，**未修**（见 ADR-55 §未验证）。
   ⛔ **输出侧放宽的漏判面未量化**（正则词组合，会漏掉某些教唆形态）。
   ⚠️ **同一口径已推广到 `illegal` / `harm_others`（ADR-56，2026-09-28）**：
   - `illegal` 的裸词 `诈骗` 与 `(教|教我).{0,6}(PUA|操控…)` 请求形态 → `INPUT`
     （实测：助手给**正常防骗科普**时输出含"诈骗" → 曾被拦成拒答 → 用户失去有用信息）
   - `harm_others` 的请求形态 `(想|要|计划)(杀|害|报复)(他|她|人)` → `INPUT`
     （输出侧会误中"**我想报复他**这句话背后…"这类**共情解读**）
   - 输出侧新增 `illegal_incite` / `harm_others_incite`（建议类词 + 危险词同句相邻）
   - ✅ 保留 `BOTH`：`PUA教学`（请求用语，误伤风险低）
   ⛔ **已知限制**：`我被诈骗了，钱能追回来吗` → 输入侧 `illegal` 裸词拦 → 拿到拒答
     （**受害者咨询也被拦**，未修，"宁可严"）
   ⚠️ **`harm_others` 补了「了」字形（ADR-57，2026-09-28）**：原正则要求三词紧邻 →
     `我想杀了他` 这类**口语最自然的说法反而漏掉**（L3 漏判）。加 `了?` 后：
     同批样本**新增命中 4 条、新增误报 0 条**。⚠️ 仍未覆盖 `我要是能杀了他就好了`。
3. **反操纵**：「教我 PUA/操控」类请求 L3 阻断（06 §4），并纳入 Golden Set 禁用词回归（09 §4）。
4. **个保法**：注销流程级联删除（ADR-5）；隐私政策明示「进化模块会在您同意后将匿名化技巧沉淀进知识库」的单独同意开关。
5. **IP 政策（ADR-12）**：沙盘角色一律原创（原型标签 + 自创名 + AI 头像）；护栏拦截「扮演知名角色」请求；生成图禁用「某画师风格」prompt；AI 生成图片加显式标识（《人工智能生成合成内容标识办法》）。
6. **未成年人保护**：沙盘/陪伴属性功能配防沉迷与使用时长提醒；注册环节年龄声明。
7. **诊断类能力（远期附录，SRS §6）**：认知诊断/人格诊断报告/关系健康度仪表盘上线前置 = 本文档合规评审（ADR-10 定稿），**科学性与合规未证前不做**（01 §3 / 11 §5.2）。

## 6. 数据安全

- 私信加密：AES-256-GCM 按租户派生密钥（ADR-4）。
- 日志脱敏：生产日志严禁出现用户输入/模型输出原文，一律 `content_hmac` 或长度+前 10 字符。
- 传输：全站 HTTPS；SSE 经 Nginx 需确认不落访问日志 body。
- **图片输入（ADR-11）**：截图含他人头像/昵称/手机号——分析结论与 HMAC 落库，原图仅对象存储保留、随消息级联删除；上传时前端明示「请勿上传含他人隐私或亲密内容的图片」；输入护栏拒收亲密/涉未成年人图像。

⚠️ **关于"出域"的口径（2026-09-28 修正 —— 第一版写重了）**：
1. ⚠️ **JEV 出域不是新的隐私类别**。本表前三行（DeepSeek / 硅基流动 / JEV）送的都是
   **用户原话或原文**，其中 **DeepSeek（LLM 主链）与硅基流动（embedding/rerank）
   在 JEV 之前就一直在送**。JEV 只是**清单里多一个第三方**，不是新增了一类风险。
   本表的价值是**把已有事实列全**，而不是"JEV 让隐私变差了"。
   → 第一版写成"JEV 未做知情同意设计"，**等于把一个既有问题的责任安到了新来的那个身上**；
   若要谈知情同意，该谈的是**整条链**（含 DeepSeek），不该单点针对 JEV。
2. ✅ **本表此前根本不存在 —— 这是真缺口，已补**。纪律：**新增出域依赖必须同步更新本表**
   （与 ADR-46「换组件要逐字段核对载荷」同族：新增面不许无痕）。
3. ⚠️ JEV 的真差异在**治理**、不在隐私：它是**唯一绕过 `LlmGateway`** 的外部依赖
   （不受闸门/熔断/计量/准入约束）。它不生成文本、不做 embedding，
   **宕机不影响可用性**（失败即回退到 LLM 路径）。
