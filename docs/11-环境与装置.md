## 二、脚本与测量的硬规矩

- ⛔ **脚本里禁用 `rm`**：平台 safe-delete 会把文件移走，测量类脚本会**静默得出错结论**。用带时间戳的文件名。
- ⛔ **判端口用 python `socket.connect()`，不要用 `netstat`**：
  端口保留时 `bind` 报 `WinError 10013` 而 `netstat` 看不见；
  且 `netstat | grep x | head -1 || echo` **永远会 echo**（末位是 `head`）。
- ⚠️ **后台进程会被沙箱回收**：长跑必须在**同一条命令内**串起"启动→等待→测试→收尾"。
  等待启动要检测 `BUILD FAILURE` / `cancelling refresh attempt` **提前退出**（否则白等 6 分钟）。
  bash 里 `A=1 && ... && java ... &` 的 `&` 作用于**整条链** → 后续变量为空，**要用脚本文件**。
- ⛔ **不要用 shell 写含反引号 / 行首 `>` 的 Markdown**（会被当命令替换/重定向执行）→ **用文件写入工具**。
  同理：**超长的 heredoc 容易被 shell 解析错**（引号嵌套）→ 写成 `.py`/`.sh` 文件再执行。
- 管理端点前缀是 **`/api/actuator/...`**（`server.servlet.context-path=/api`）；按 `/actuator/...` 抓会 404。

## 三、凭据

- **凭据在 `target/classes/application-local.yml`**（**gitignored**）→ ⛔ **不要 `mvn clean`**（会删掉它）。
  新增凭据也写这里；`scripts/prod_env_from_local.py` 把它提取成环境变量（输出 `export KEY=value`）。
- ⛔ **验证陷阱（实测踩过）**：profile yml 里的**字面值优先于**主 yml 的 `${SF_API_KEY:}` 占位符
  → **把环境变量置空 ≠ 真的缺 key**。要真缺，得用优先级更高的环境变量覆盖**配置项本身**
  （`APP_SILICONFLOW_API_KEY=''`）。
  📌 **通用规矩：验证"缺 X 会怎样"之前，先用一个可观测副作用确认 X 真的没了**
  （首版没查 → 日志里该 key 出现 0 次 → 测出来是**假绿灯**）。
- `eval "$(脚本)"` **不会 export** → 变量只留在本 shell，派生的子进程看不到。加载脚本要输出 `export K=V`。

## 四、git（这个仓库的 `.git` 不完整）

- ⛔ **禁止 `git stash`**：会清空 `refs/heads/main` 与 index。
  恢复：`git fetch origin main` → `git update-ref refs/heads/main <sha>` → `git read-tree HEAD`。
- ⚠️ 判断"远端有没有我的提交"**只能看 `git ls-remote origin refs/heads/main`**（别信"已推送"的口头结论）。
- ⚠️ **多会话并行改同一工作区**：`git status` 会混入别人的改动；下"没做"结论前先读文档正文；
  提交时**只 `git add` 本轮自己的文件**，别把别人的未提交改动裹进来。

### 一条必须保留的装置习惯：**前提断言**

在跑任何"效果/代价"测量之前，先断言**这条链路真的被走到了**。例如压测前断言
"这条 prompt 确实触发了检索 + 重排"（`RAG_RETRIEVAL` ≥1 且 `Rerank call` ≥1）。
实测价值：上一轮这条断言直接拦下了一次"重排根本没参与"的压测 ——
否则会得到一组**看起来很正常**的 TTFT 数字，而测的是另一条链路。
