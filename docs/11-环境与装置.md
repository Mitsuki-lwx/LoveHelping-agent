## 二、脚本与测量的硬规矩

- ⛔ **脚本里禁用 `rm`**：平台 safe-delete 会把文件移走，测量类脚本会**静默得出错结论**。用带时间戳的文件名。
- ⛔ **判端口用 python `socket.connect()`，不要用 `netstat`**：
  端口保留时 `bind` 报 `WinError 10013` 而 `netstat` 看不见；
  且 `netstat | grep x | head -1 || echo` **永远会 echo**（末位是 `head`）。
- ⚠️ **后台进程会被沙箱回收**：长跑必须在**同一条命令内**串起"启动→等待→测试→收尾"。
  等待启动要检测 `BUILD FAILURE` / `cancelling refresh attempt` **提前退出**（否则白等 6 分钟）。
  bash 里 `A=1 && ... && java ... &` 的 `&` 作用于**整条链** → 后续变量为空，**要用脚本文件**。
- ⛔ **不要用 shell 写含反引号 / 行首 `>` 的 Markdown**（会被当命令替换/重定向执行）→ **用文件写入工具**。
  同理：**超长的 heredoc 容易被 shell 解析错**（引号嵌套）→ 写成 `.py`/`.sh` 文件再执行。
- 管理端点前缀是 **`/api/actuator/...`**（`server.servlet.context-path=/api`）；按 `/actuator/...` 抓会 404。

### 3.4 其他踩坑

- ⛔ **验证陷阱（实测踩过）**：profile yml 里的**字面值优先于**主 yml 的 `${SF_API_KEY:}` 占位符
  → **把环境变量置空 ≠ 真的缺 key**。要真缺，得用优先级更高的环境变量覆盖**配置项本身**
  （`APP_SILICONFLOW_API_KEY=''`）。
  📌 **通用规矩：验证"缺 X 会怎样"之前，先用一个可观测副作用确认 X 真的没了**
  （首版没查 → 日志里该 key 出现 0 次 → 测出来是**假绿灯**）。
- `eval "$(脚本)"` **不会 export** → 变量只留在本 shell，派生的子进程看不到。加载脚本要输出 `export K=V`。
- ⛔ **不要在终端 `cat` / `tail` / `grep` 凭据文件**（会把明文刷进会话记录与日志）
  → 用 `sed 's/=.*/=<SET>/'` 或只看键名。**2026-09-28 本人已在 `tail` 时失手一次。**

## 四、git（这个仓库的 `.git` 不完整）

- ⛔ **禁止 `git stash`**：会清空 `refs/heads/main` 与 index。
  恢复：`git fetch origin main` → `git update-ref refs/heads/main <sha>` → `git read-tree HEAD`。
- ⚠️ 判断"远端有没有我的提交"**只能看 `git ls-remote origin refs/heads/main`**（别信"已推送"的口头结论）。
- ⚠️ **多会话并行改同一工作区**：`git status` 会混入别人的改动；下"没做"结论前先读文档正文；
  提交时**只 `git add` 本轮自己的文件**，别把别人的未提交改动裹进来。

### 一条必须保留的装置习惯：**前提断言**

在跑任何"效果/代价"测量之前，先断言**这条链路真的被走到了**。例如压测前断言
"这条 prompt 确实触发了检索 + 重排"（`RAG_RETRIEVAL` ≥1 且 `Rerank call` ≥1）。

否则会得到一组**看起来很正常**的 TTFT 数字，而测的是另一条链路。

## 七、环境坑速查（2026-09-28 从长期记忆迁入）

> 这些是**实测踩出来的**，每次改动或实测前扫一遍。⛔ 标记的会导致**静默错误**（最难查的一类）。

- ⛔⛔ **`resp.read(4096)` 测 SSE 首帧必错** —— `read()` 要读满才返回，会把"流结束"记成"首帧"。
  **必须 `read1()`**。（曾据此误判"首字节占位无效"整整一轮。）
- ⛔ **「独立 event 名未监听会被丢弃」是错的**：本项目前端是 **fetch 手写解析** → 凡 `data:` 行一律当正文
  → `status` 的 JSON **会被拼进气泡**。→ **凡 SSE 增事件必须同时改前端分流**
  （`front/src/api/index.js`），且**只对 status 分流**（`error`/`advice` 载荷是要显示的正文）。
- ⛔ **对照实验必须逐臂报量具健康**（PKIX TLS 失败 / 上游超时 / embedding 失败 / L3 拦截），
  只报"应用层 ERROR=0"不够 —— 两臂条件不等价时对照无效（ADR-53 实证）。
  ⚠️ JVM 侧 TLS 会间歇 `PKIX path building failed`（**跟时间跑不跟臂跑**）；系统信任库直连同域名 OK
  → 疑与代理/Clash fake-ip 相关，**未归因**。
- ⚠️ **探针里 f-string 写进 dict 字面量 = 构造时一次性求值** → 同 arm 多轮共用 chatId → RedisSaver
  恢复 checkpoint → `GRAPH_PATH` 累积（被误读成"图在自转"）。
  **凡按用例 id 生成资源名，必须编入本次运行标识。**
- ⚠️ **测前缀缓存/任何门槛型现象，样本必须长到超过门槛**（591 token 样本全落在地板值 → 现象没出现）。
- ⛔ **判据里 grep 裸数字必误报**（grep `402` 会命中随机用户名与 traceId）→ **必须带上下文**。
- ⛔ **本机 PortableGit 的 `astextplain` 依赖缺失的 `file` 命令** → 凡**触及 `*.doc/docx/pdf` 的提交**，
  `git show` / `git diff` **直接失败**：`astextplain: line 10: file: command not found` /
  `fatal: unable to read files to diff` → **打断「用 git 反查历史」这条主力手段**（本仓交接纪律依赖它）。
  已修：`~/.config/git/attributes` 把 Office/PDF 一族设 `-diff` + `core.attributesFile` 指向它（**仓库零改动**）。
- ⛔ **脚本禁用 `rm`**（safe-delete 会把文件移走 → 测量脚本静默出错）→ 用带时间戳文件名。
- ⚠️ **`spring-boot:run` 不自动编译**（前端产物在 `resources/static`，服务加载 `target/classes`）
  → 实测前必须 `bash logs/mb.sh compile`。
- ⛔ 判端口用 python `socket.connect()`；`netstat|grep|head||echo` **永远会 echo**。
- ⚠️ **后台进程会被沙箱回收** → 长跑要在**同一条命令内**串"启动→等待→测试→收尾"。
- **主 app 强依赖 mcp-server**（缺了整个 context 崩，不是降级）；**端口随机** → 从启动日志读 base。
- ⛔ `eval "$(scripts/prod_env_from_local.py)"` 注入的变量**传不进 python 子进程** → 探测脚本**自己读** yml。
- ⚠️ **浏览器实测四坑**：页面在 `/api/` 下（base+context-path）· 输入框是 `.chat-input`(`input`)
  **不是 textarea** · CDP 绑定时序要用**真实登录** · 同一 eval 里填完就点按钮会读到 nextTick 前的旧 `disabled`。
- ⛔ **`git push` 走 SSH:22 会被代理挡掉**（2026-09-28 实测：`Connection closed by 198.18.0.73 port 22`，
  198.18.0.0/15 是 Clash 的 fake-ip 段）。✅ **走 GitHub 的 443 通道即可**：
  `GIT_SSH_COMMAND="ssh -p 443 -o StrictHostKeyChecking=accept-new" \
     git push git@ssh.github.com:Mitsuki-lwx/LoveHelping-agent.git HEAD:main`
  ⚠️ 推送后**必须**用 `git ls-remote` 复核（同一条 GIT_SSH_COMMAND）—— 本仓有过"声称推送完成实际被中断"的历史。
- 管理端点前缀 `/api/actuator/...`；写 Markdown 用文件写入工具。
- ⚠️ **脚本/装置放 `logs/` 等于没写**（该目录被 gitignore）→ 装置一律入仓到 `scripts/`。
