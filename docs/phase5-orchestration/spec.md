# spec.md — 业务编排图（OrchestrationGraph）

> **问题**：聊天入口三裂——普通对话（ChatEntry→ChatExecutor）、工具任务（ChatEntry→ReactAgent）、沙盘（独立 `/sandbox/chat` 直连 ChatExecutor），各有各的路由与执行语义。流程不可见、不可观测、不可插拔（ReactAgent 是黑盒），沙盘用不上知识库，RAG advisor 声称已接线实则未接。
>
> **方案**：用 graph-core 的 StateGraph **自绘一张业务编排图**作为唯一聊天入口——开始 → 简单问题直答 → 类型路由（沙盘/普通/Agent）→ 处理节点 → 统一检查节点 → 工具循环 → 结束。节点/边/条件全部显式，可观测、可加 hook、可改流程。沙盘收编入图并接完整 RAG。
>
> 技术决策见 **ADR-19**；与 ADR-8（采用 ReactAgent）冲突部分已记修订。

---

## 目标用户

所有 C 端用户 + 后端开发者。对用户：任何聊天/沙盘/任务请求走同一通道、行为一致。对开发者：流程是一张可读的图，定位问题看节点与 hook，改流程改边。

## 能力清单

| ID | 能力 | 说明 |
|----|------|------|
| CAP-1 | 统一图入口 | 普通/沙盘/Agent 请求全部进入一张 StateGraph，入口职责收敛 |
| CAP-2 | 简单问题直答 | 问候/一句话闲聊/无需检索与工具 → 跳过类型路由直接回答，路径最短 |
| CAP-3 | 类型路由 | 非简单问题按规则分派到 沙盘（会话上下文人设）/ 普通回复 / Agent 工具任务 |
| CAP-4 | 图内工具循环 | LLM 节点 ↔ 工具节点条件边循环；有工具调用回到 LLM，无工具调用结束，步数上限兜底 |
| CAP-5 | 统一检查节点 | 护栏（L3 阻断/情绪刹车/记录）、话术三级激活标记、质量骨架在生成后统一检查 |
| CAP-6 | Hook 机制 | 节点生命周期 hook（进入/退出/工具前/工具后/错误/结束/简单命中），可插拔可观测 |
| CAP-7 | 图级可观测 | 每节点耗时指标、图路径追踪（trace 记录走了哪些节点）、状态快照日志 |
| CAP-8 | 沙盘入图 | 沙盘作为图的一种模式：人格 prompt + 沙盘记忆 + 动态情绪保留，不再独立通道 |
| CAP-9 | 沙盘/普通接知识库 | RetrievalAugmentationAdvisor + QueryRewriter 真正接线，普通与沙盘节点检索增强 |
| CAP-10 | 兼容不破坏 | SSE 协议与事件（含 event: advice）不变；agent_task/message 表/LlmGateway/护栏全部保留为图内组件 |

## 图结构（骨架）

```

                     │            START             │  guardrailCheck + 限流（保留现状）
                     └──────────────┬───────────────┘
                                    ▼
                     ┌──────────────────────────────┐
                     │      简单问题判定（规则）      │  ← hook: onSimple
                     └──────┬───────────────┬───────┘
                       是(直接回答)         否
                        ▼                   ▼
                ┌──────────────┐   ┌────────────────────┐

                       │ │ 沙盘节点  │ │ 普通节点  │ │  Agent 节点(LLM)    │
                       │ │(人设+记忆 │ │(含RAG注  │ │  + 知识库工具等     │
                       │ │ +RAG)    │ │ 入)      │ │                     │

                       │   │ (护栏复检/话术激活/  │    有工具调用?
                       │   │  质量骨架)          │─────────┐
                       │   └───────┬────────────┘         │
```

- **简单问题判定**：规则（问候/一句话/已满足的短问答），命中走"回答节点(简)"——最短路径不检索不调用工具。
- **沙盘模式**：进入条件 = 请求带沙盘会话上下文；节点输出人格 + 记忆注入 + RAG。
- **工具循环收敛**：LLM 节点产出带或不带工具调用；带 → 工具执行 → 回 LLM；不带 → 检查 → END；循环步数上限（沿用 15）兜底，超限走错误路径。
- **统一检查节点**：对**最终回复**做复检（护栏语义复核、话术三级是否需激活补充、质量骨架），单点出口便于加检查项。

## 状态（State）字段

- 请求：message、chatId、mediaIds、userId/tenantId
- 上下文：会话记忆窗口、知识库检索上下文、沙盘人设/记忆/情绪
- 执行：route 类型、工具调用记录、步数、可观测埋点集合
- 输出：文本流 + 结构化事件（advice 等）

## Hook 清单（CAP-6，具体点位随实现对齐 graph-core 拦截机制）

| Hook | 触发时机 | 用途示例 |
|------|---------|---------|
| onStart / onEnd | 图首尾 | 耗时总览、agent_task 完成回调 |
| onSimple | 简单问题命中 | 统计短路径命中率 |
| onTypeRoute | 类型路由决策后 | 统计 沙盘/普通/Agent 分布 |
| onNodeEnter / onNodeExit | 每个节点进出 | 节点耗时、状态快照、Tracing 埋点 |
| onToolStart / onToolEnd | 工具执行前后 | 工具耗时/成败指标、🔧 SSE 事件 |
| onError | 节点抛错/超步数 | 错误降级文案、任务 FAILED |

## 可观测（CAP-7）

- 每节点耗时 counter/histogram（图表：`orchestration.node.duration{node,route}`）
- 图路径 trace：一次请求走过的节点序列（日志 + tracing span）
- 状态快照：关键节点（简单判定/类型路由/工具循环后）记录输入输出摘要
- 冒烟断言：新增"图路径"检查项（简单请求只走 2 节点，Agent 请求走过工具循环）

## 兼容与迁移（CAP-10）

- SSE 端点/协议不变（含 `event: advice`），前端零改动
- `agent_task` 状态机：图执行完成回调接入（现状 ChatService 承担）
- `message` 表记忆：窗口注入 + 落库语义不变
- **删除面**（同一 Phase 完成，AGENTS.md 不并行原则）：ChatEntry 的"路由 + 分发"职责、沙盘独立 `/sandbox/chat` 直连逻辑（端点保留、内部改走图）、ReactAgent
- RAG 现状 gap 修复：RetrievalAugmentationAdvisor 从"类存在未接线"变为真实装配

## Out of Scope

- 并行分支（多条链路同时跑的图）——串行优先，数据验证后再评估
- 人工介入（interrupt/resume 暂停图等人确认）——远期
- 多 Agent 协作/子图编排——本期单图
- 图的持久化编排定义（DB/文件存流程图）——先代码固化，DB 化后续演进
