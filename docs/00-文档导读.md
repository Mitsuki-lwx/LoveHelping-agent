## 阅读顺序建议

- **新加入的开发**：01 → 11（SRS）→ 02 → 05 → 06。
- **做重构实施**：10（路线图）为主线，遇到争议回看 03（ADR）。
- **评审接口**：05 + 07。

## 三条贯穿全文档的原则

1. **现状优先于愿景**：所有设计分「现状（As-Is）」与「目标（To-Be）」，目标若未进入路线图就不算承诺。
2. **每个决策都有代价**：ADR 中必须写"放弃了什么"，不接受只有优点的方案。
3. **情感类产品的信任是生死线**：隐私、心理边界、误伤控制相关需求一律 P0。

## 第四条原则（硬性纪律）

4. **每次修改必须端到端验证**：完成定义 = 编译通过 + 相关单测通过 + 触达面的 E2E 冒烟通过（`09 §7`）。只有编译通过不算完成；本地依赖不可用时必须显式声明"未做 E2E 验证"并登记待验证项。
