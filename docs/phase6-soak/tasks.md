# Phase 6 收尾 · 长时混合负载稳定性 — 任务拆分（tasks）

> 立项：2026-09-16
> 承接：`docs/phase6-concurrency/`（ADR-29）。该轮唯一未验收项就是本任务。
> 前置阅读：`docs/09-测试策略.md` §6（性能口径）、§8.8（Phase 6 实测）、`docs/03` ADR-29。

## 1. 目标

关闭 Phase 6 的**唯一未验收项**，并顺带对已提交的 `387a929` 做一次**独立复核**（不引用前一会话的自述结论）：

1. **真实 E2E 复验**：`387a929` 声称 22/22，本轮自己跑一遍，拿到可查证据。
2. **30 分钟混合负载稳定性**：验证在持续负载下**没有资源泄漏与单调劣化**——
   队列深度不持续增长、连接池稳定、已发放的准入额度（permit）能全部回收、无 5xx。

本任务**不是**新的功能开发，而是把已实现的东西**验到能签字**。

## 2. 为什么单独立项

`docs/09` §6 的验收表里，"混合负载 30 分钟"一行从 2026-09-06 立项起一直挂着
（§6.1 实施步骤第 6 条：`⏳ 30 分钟混合负载稳定性：尚未执行`）。
Phase 6 的其余验收（编译 / 170 单测 / 22 项真实 E2E / Langfuse 11/11 / 阶梯压测）都已闭环，
只有它是空的。短时压测（几十秒级别的阶梯）**测不出**慢速泄漏：
permit 泄漏、连接未归还、队列深度缓慢爬升这类问题需要**时间**才能显形。

## 3. 范围

### 做
1. **独立复验 E2E**：起真实栈（mcp-server 8125 + 主应用 local profile），跑 `scripts/e2e_live.py`，
   证据落 `outputs/`。
2. **长时采样**：新增 `scripts/soak.py`——固定"在途 ≈ 闸门(24)"的多用户混合负载，持续 30 分钟，
   周期性采集 `online.inflight.current` / `online.queue.depth` / Hikari 池 / JVM 堆 / 拒绝分类，
   原始采样落 JSONL，汇总落 JSON。
3. **判定与落档**：按 `checklist.md` 逐条判定；结果写入 `docs/09` §8.9 与 ADR-29 的"未验收"行。
4. **问题修复**：若 soak 暴露真实缺陷，**记录 → 定位 → 修复 → 重跑**（缺陷修复属于本任务范围内，
   因为它正是本任务的目的）。修复必须补单测。

### 不做（防范围蔓延）
- 不改阈值参数（`wait-ms` / `queue-capacity` / `max-inflight`）来"把测试跑绿"。
- 不换/不叠加 LLM 厂商；不引入 MQ；不做跨实例容量协调（ADR-23 既定）。
- 不动检索、提示词、业务编排；**不启用 rerank**（已两轮实测负收益，ADR-25 + §8.7 G6）。
- 不做多租户维度扩建（ADR-13 冻结）。
- 不以"短跑通过"代替长跑；不以"mock"代替真实 LLM。

## 6. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 真实 LLM 调用成本 | 24 在途 × 30 分钟是**真实**模型调用 | 用轻量 prompt；不跑满 30 分钟之外的探索性档位；额度耗尽即停并保留数据 |
| 厂商配额波动 | 上游 429 会污染结论 | 拒绝分类里把厂商 429 与闸门 4003 分开；厂商 429 单独计数并显式报告 |
| 环境不可控 | Windows + 杀软 + 沙箱可能干扰长时进程 | 先短跑热身确认链路，再开长跑；异常退出保留已采样数据 |
| Langfuse 需 Docker | 用户侧拉起，Agent 拉不动 | 本轮**不把 Langfuse 列入门禁**（ADR-24/26 已在 `387a929` 验收）；若实例在跑则顺带核对 |
| 把"跑绿"当目标 | 为了让数字好看而调参 | 参数在本轮**冻结**；任何调参必须另立任务并说明代价 |
