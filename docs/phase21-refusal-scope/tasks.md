> 背景：`.omp` 会话（2026-09-27 13:16~21:12）实施了 ADR-48 处置选项 ①（改 scope 措辞），
> 但该改动**混在 `5d8c4c3`（ADR-48 主链切换）里**，commit message 一个字没提，
> `docs/03-技术决策记录.md` 也**没有对应 ADR**。ADR-48 原文要求：
> 「这属于提示词改动，需另立 ADR，且**改完必须用同一套两臂对照复验**（单次观察会得出错误结论）」。
> **该对照从未执行**。本轮补账。

## 1. 目标

| # | 目标 | 验收方式 |
| --- | --- | --- |
| G1 | 让 scope 措辞**可切换**（strict / adjacent-help 两版），从而能构造单变量对照 | 启动日志自报生效措辞版本；单测锁两版文案 |

## 2. 为什么必须做对照（不能只跑新措辞）

ADR-48 记录的那次测量是 **`space-bunny-alpha` vs `glm-4-flash` 两个模型**的对照，
主链与兜底都是两个不同的模型。现在（ADR-51 之后）：

- 主链 = DeepSeek 官方 `deepseek-flash`
- **降级链为空（ADR-52）**，原 B 臂 bigmodel 实测 HTTP 400
- → **ADR-48 用的那套对照已不可复现**

于是只剩一个致命歧义：

> 若在 `deepseek-flash` 上跑新措辞，看到 0 拒答 ——
> **无法区分**「(a) 措辞修复有效」与「(b) deepseek-flash 本来就不怎么拒答」。

ADR-47 的第一版结论（"160 vs 726 = A 臂能力更差"）就是这么错的：
**拿一个相关数字当因果**。本轮不能重犯。

→ **必须造同 provider、只差 scope 措辞的单变量对照。** 这是本轮唯一的结构性改动（G1）。

## 3. 问题现状（读码核实，非推断）

### 3.1 修复已在代码里

`ChatExecutor.java:112-124` 的 `SYSTEM_PROMPT` scope 段已改成 A/B 两类边界：

```
(A) 情感相邻的身心状态（失眠/焦虑/情绪低落…）——**不要硬拒**。
    先给 2-3 条具体、可执行的建议…再用一句自然的话把话题轻轻接回关系维度
(B) 明显无关的事务性请求（写代码/写作业/做菜谱…）——**才用一句话礼貌拒绝**
判断准则：**拿不准就归入 (A) 先帮再接回，宁可多帮一句，不要无谓拒答。**
```

`git log -S "不要硬拒"` → 引入提交 **`5d8c4c3`**（commit message 只讲模型切换）。

### 3.2 但修复有**第二处同源实现**未被改

`CapabilityRouter.isOffTopic`（规则层，零 LLM）是**另一条独立的域外拦截路径**，
命中即进 `OffTopicNode`，输出固定话术、完全不过 LLM：

```java
// CapabilityRouter.isOffTopic
boolean hit = message.matches("(?i).*(" +
    "帮我?写.{0,12}(代码|程序|脚本|函数|算法|冒泡|二分|递归|排序|作业|论文|简历|python|java|sql)|" +
    "写.{0,8}(代码|程序|python|java|...)|" +
    "(二分|冒泡|快排|排序|递归|二叉树|链表|动态规划).{0,6}(算法|实现|代码)|" +
    "leetcode|力扣|编程题|作业|论文|开题|答辩|毕业设计|简历|ppt|excel表格|表格公式|" +
    "翻译.{0,6}(文档|句子|文章)|数学题|物理题|化学题|电路).*");
```

⛔ **这条路径锁的是 (B) 类（写代码/写作业/翻译技术文档），与 scope 措辞的 (B) 类方向一致 ——
所以它不会被本次修复破坏**，但它意味着 **(B) 类的拒答有两道闸**。
⚠️ 由此产生一个**量具陷阱**：`G3`（写代码）组大概率**根本到不了 LLM**，
它的拒答来自 `OffTopicNode` 而非提示词 → **G3 验的不是 scope 措辞，是规则层**。
这不使 G3 无价值（G3 是修复的**反向风险**护栏：证明"该拒的还拒着"），
但**必须在结论里说清 G3 走的是哪条路径**，否则会被误读成"提示词拒绝了写代码"。

### 3.3 scope 措辞目前**硬编码在 Java 常量里**

`SYSTEM_PROMPT` 是拼接字符串常量，没有配置开关 → **无法在不重新编译的前提下做对照**。
这是 G1 的直接由来。

## 4. 做什么

### T1 scope 段抽成可切换（`app.chat.scope-wording`）

- 新增配置项 `app.chat.scope-wording`，取值 `strict`（修复前原文）/ `adjacent-help`（当前，默认）
- `ChatExecutor` 按该值从两段常量中二选一
- **启动日志自报生效版本**（`[scope-wording] ...`）——
  ⚠️ 不能让对照臂"以为"切了：臂真的切没切，必须有可查询证据，不能靠读代码推断
- 单测：两版文案都被断言存在 + 默认值是 `adjacent-help`（防默认值被误改成 strict 而无声）

### T2 三组问题复验装置

`scripts/probe_refusal_scope.py` + `scripts/run_phase21_refusal.sh`：

| 组 | 问题 | 期望 | 作用 |
| --- | --- | --- | --- |
| **G1** | 失眠 / 压力大睡不着 | 实质回答（0 拒答） | 修复目标 |
| **G2** | 约会看手机被说她自私 | 实质回答 | 回归护栏（防改坏） |
| **G3** | 帮我写一段 Python 快排 | 礼貌拒绝 | **反向风险**（防把该拒的放开） |

⚠️ 只测 G1 是不够的 —— 放宽拒答口子天然有"顺带把 (B) 类也放开"的风险，
**不测就等于没验**。这与 ADR-48 当初只看一个问题的做法不同，是本轮的补强。

两臂只差 `ARM_W`（scope 措辞），`OPENAI_BASE_URL/MODEL/API_KEY` 全同，
评测期 `APP_SCHEDULER_MASTER_ENABLED=false` 冻结库。

## 5. 不做什么

- **不改措辞内容本身**。`.omp` 写的 A/B 措辞先原样复验；本轮只加开关，不做措辞调优。
  若复验显示措辞无效，那是一个**新的决策**，不在本轮偷偷改。
- **不做答案质量 A/B**（`answer_eval.py` 口径）—— 那是 P2，本轮不碰，不得声称答案质量变好/变差。
- **不动 `CapabilityRouter` / `OffTopicNode`**。它们是 (B) 类的规则层兜底，与本次修复方向一致；
  改它们属于另一个决策。
- **不补兜底 provider**（P1）。
- **不声称"用户可见行为变好"**，除非 G1 组两臂对照真的显著。

## 7. 已知代价 / 风险

- **配置项多一个开关**，两条措辞并存于代码里（约 14 行）。这是"可对照"的必要代价；
  若不做，本轮只能出一句"现状看起来不拒答了"——**那正是 ADR-47 翻车的形状**。
- `strict` 版在生产是**已知更差**的版本（会无谓拒答）。它只应作为对照臂存在，
  启动日志会标 `[对照臂]` 提醒，文档写明"不建议在生产启用"。
- G3 走的是规则层（§3.2）→ 它的通过**不能证明提示词的 (B) 类有效**，
  提示词的 (B) 类在本轮**未被独立验证**（要验需构造一个不命中 `isOffTopic` 但明显事务性的问题，
  如"帮我算一下这个月的账" —— 列为已知未验证项）。
