## 2. 架构与端口

```
                         ┌──────────────┐
 浏览器 ──:8088/api ──▶ │     app      │  Spring Boot 单 jar（含前端 + Flyway + 启动自举 embedding）
                         └──┬───┬───┬───┘
                    MCP_URL  │   │   │ jdbc
      ┌───────────────┐      │   │   ▼
      │  mcp-server   │◀─────┘   │  mysql:3306（agentdb）
      │  :8125（工具面）│         │
      └───────────────┘         ├─ postgres:5432（pgvector，RAG 向量库）
                                └─ redis:6379
```

- 上下文路径 `/api`；SSE、登录、静态资源均在 `/api` 下，同源无需 CORS。
- mcp-server 独立容器（主应用启动即连接，MCP client 必须可达——见 MEMORY 8125 老坑）。

## 3. 配置外部化（发布前改造，本次完成）

| 项 | 环境变量 | 说明 |
|---|---|---|
| Profile | `SPRING_PROFILES_ACTIVE` | 默认 `local`（开发）；compose 恒为 `prod`。**生产禁用 local**（含明文密钥/本地路径/DEBUG 日志） |
| 主模型 key | `OPENAI_API_KEY` | 智谱 BigModel（base `OPENAI_BASE_URL` 默认 bigmodel，`OPENAI_MODEL` 默认 glm-4-flash） |
| embedding/备模型 | `DASHSCOPE_API_KEY` | 检索 embedding + 降级 qwen-plus |
| JWT | `JWT_SECRET` | **必填 ≥32 字符**；缺失启动拒绝（fail-fast） |
| 管理端点 | `ADMIN_API_KEY` | 请求头 `X-Admin-Key` |
| DB/中间件 | `MYSQL_HOST/PASSWORD`、`PG_HOST/PGVECTOR_PASSWORD`、`REDIS_HOST` | 容器内 host 名由 compose 注入 |
| mcp 地址 | `MCP_SERVER_URL` | 默认 localhost:8125；compose 内 `http://mcp-server:8125/mcp` |

## 4. Docker 一键部署

```bash
# ① 准备密钥（模板 → 实值）
cp .env.example .env
#    编辑 .env：MYSQL_PASSWORD / PGVECTOR_PASSWORD / OPENAI_API_KEY / DASHSCOPE_API_KEY / JWT_SECRET / ADMIN_API_KEY
#    （JWT_SECRET 生成：openssl rand -hex 32）

# ② 构建并启动（首次会拉 mysql/pgvector/redis 镜像 + 编译两个 Java 服务）
docker compose up -d --build

# ③ 观察启动（PG 首启 embedding 需几分钟）
docker compose logs -f app

# ④ 健康检查
curl http://localhost:8088/api/actuator/health
# 前端：http://localhost:8088/api/

# ⑤ 停止/清理
docker compose down            # 停服务（数据卷保留）
docker compose down -v         # 连数据一起删（重建全新库）
```

首次启动后注册第一个账号即可使用（公开注册恒为 USER；管理端点走 X-Admin-Key，无需 ADMIN 账号）。

## 5. CD：镜像发布与自动部署（2026-09-07 落地）

```bash
# ① 打 tag 触发流水线（ci 全绿后）
git tag v1.0.0 && git push origin v1.0.0

# ② release 流水线自动：构建双镜像 → push GHCR（lovehelping / lovehelping-mcp）
#    → 若配置了 DEPLOY_HOST secrets 则 ssh 到服务器自动升级
```

- 本地/测试直接构建：`docker compose up -d --build`（compose 同时保留 build 与 image，二选一）。
- 服务器部署（人工/半自动）：服务器预置 `/opt/lovehelping/`（docker-compose.yml + .env），
  然后 `TAG=v1.0.0 ./scripts/deploy.sh`（pull → up -d → 等健康）。
- 需要配置的仓库 Secrets：`DEPLOY_HOST` / `DEPLOY_USER` / `DEPLOY_SSH_KEY`
  （不配则只发布镜像，部署保持人工——release job 自动跳过）。
- 回滚：`TAG=上一版本 ./scripts/deploy.sh` 一条命令回到旧镜像（数据卷不动，无损）。

## 6. 常见问题

| 症状 | 原因/处理 |
|---|---|
| app 反复重启 | mcp-server 未就绪（depends_on service_started + restart=unless-stopped 会自动拉起；看 `docker compose logs app` 是否 "Failed to connect ... 8125"） |
| PG 首启慢 / embedding 报 429 | 首次全量向量化 71 篇 × embedding；调小不影响正确性，重试会续传（增量同步按 doc_hash） |
| 改 .env 后不生效 | `docker compose up -d` 重建 app；DB 密码改动需 `down -v` 重建卷 |
| JWT_SECRET 未设 | 应用拒绝启动（安全设计）——按报错补 .env 即可 |

## 8. 灾备与运维（2026-09-07 课4）

### 8.1 备份（3-2-1）
```bash
# 手动备份（服务器上）
cd /opt/lovehelping && set -a && source .env && set +a && bash ops/backup.sh
# 定时：crontab -e 加一行（每日 03:30，脚本内含示例）
#   30 3 * * * cd /opt/lovehelping && set -a && source .env && set +a && bash ops/backup.sh >> /var/log/lovehelping-backup.log 2>&1
```
- 产出：`backups/mysql-agentdb-*.sql`（业务库）+ `backups/pg-postgres-*.dump`（向量库），保留 7 日。
- **异地副本**：把 `backups/` 同步到对象存储/另一台机器（rclone/rsync）——备份脚本只完成"3-2-1"里的本机两份，异地那份靠同步。
- dump 参数已本机实测（mysqldump 8.0：single-transaction/quick/routines/triggers，21 表完整）。

### 8.2 恢复演练（备份唯一有效验证 = 恢复过）
```bash
# 演练步骤（每季度一次，留记录）：
docker compose exec -T mysql mysql -uroot -p"$MYSQL_PASSWORD" -e 'CREATE DATABASE IF NOT EXISTS agentdb_restore'
gunzip -c backups/mysql-agentdb-最近.sql | docker compose exec -T mysql mysql -uroot -p"$MYSQL_PASSWORD" agentdb_restore
docker compose exec -T mysql mysql -uroot -p"$MYSQL_PASSWORD" -e \
  'SELECT COUNT(*) FROM agentdb_restore.users; SELECT COUNT(*) FROM agentdb_restore.audit_log;'   # 行数对账
# PG 向量库可跳过恢复演练——启动会按 document 自举重建（预算内损失=重建耗时）
```
- 关键认知：**能恢复的备份才算备份**——每月真实从 dump 起临时库验证一次，比备份脚本本身更重要。

### 8.3 错误追踪（Sentry）与告警
- 依赖已内置（io.sentry starter），配置即启用：环境变量 `SENTRY_DSN`（不配置则不初始化，零成本）。
- 启用后：未捕获异常自动聚合上报 → 配置告警（邮件/钉钉/企微）。比 Prometheus 端点先行——先有人"看到"错误，再谈自动叫醒。
- 指标告警规则（Prometheus 就绪后可加）：`llm_call` 5 分钟错误率 >10%、在线闸门拒绝数突增、audit 写入失败。

### 8.4 密钥轮换
- **JWT_SECRET**：当前改密会令所有已签发 token 失效（全员重登）。低峰轮换 + 提前公告；更平滑方案 = token 加 `kid` 支持新旧 key 并存一周期（需要时按 ADR 实施，勿在运行中直接改）。
- **LLM/DB 密钥**：随 `.env` 版本化存放（不入 git）；生产建议迁移 docker secrets / 云 KMS。双 key 灰度：新 key 上线 → 观察一周期 → 下线旧 key。
- 轮换清单触发条件：人员离职 / 疑似泄露 / 每 90 天例行。
