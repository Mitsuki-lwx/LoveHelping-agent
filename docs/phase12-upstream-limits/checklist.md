# phase12 · 验收清单

> 结论一句话：**硅基流动在 rerank/embedding 两条路上都不是瓶颈**（rerank ≥32、embedding ≥64、
> 两者混合 ≥48，**零 429**）→ `max-concurrent=16` 安全；同时修正"上游硬限 ≈24"的适用范围（只对 LLM 通道）。

## A. 装置

- [x] A1 探测脚本可复现：`scripts/probe_upstream_concurrency.py`（`--target rerank|embedding|mixed`）
- [x] A2 payload 用**真实形状**：rerank = 1 query + 20 条真实知识库块（每条截 1000 字符，与
      `top-n=20` / `max-candidate-chars=1000` 一致）；embedding = 1 条 query
- [x] A3 超时用 **30s**（生产 5s）—— 目的是**区分"限流"与"我自己超时了"**
- [x] A4 **429 与其他失败分开计数**（判读时明确写清：只有 429 才是限流）
- [x] A5 显式绕过代理（`ProxyHandler({})`），避免代理导致的连接超时污染判读
- [x] A6 每档 **2 波**（排除单波巧合）
- [x] A7 key 从环境变量读、回退时**先定位 `siliconflow:` 块**（见 C1）；脚本不打印 key

## B. 实测

- [x] B1 rerank 阶梯 1→48：**32 全成功、0 个 429**
- [x] B2 embedding 阶梯 1→64：**64 全成功、0 个 429**（p50 273ms → 711ms 线性退化但无失败）
- [x] B3 mixed（两者交替同时）8→48：**48 全成功、0 个 429** → 共用 key 无叠加限流
- [x] B4 拐点判读：rerank 48 时出现 **1 次 `TimeoutError: read timed out`（30s）**，
      已明确标注**不是限流**（无 429）
- [x] B5 记录 rerank **真实形状下的单次延迟 p50 ≈ 1.2~2.0s**
      （⚠️ 与记忆里"热态 0.39~0.43s"不一致，后者应为更短候选下的读数）

## C. 装置坑（本轮踩到并修掉）

- [x] C1 首版从本地 yml 盲搜第一个 `api-key:` → 拿到别家厂商的 key → **401（code 30014）**，
      表面像"被限流/被拒"。修法：**先定位 `siliconflow:` 块**再取；并优先用环境变量
- [x] C2 把该坑写进脚本注释与 spec §S4（规矩：**401/403 先怀疑凭据取错，再怀疑限流**）

## D. 结论与适用范围修正

- [x] D1 **`max-concurrent=16` 安全**（低于任何观测到的边界，且有余量）
- [x] D2 **修正**"提高吞吐天花板必须先提厂商配额（≈24 是上游硬限）"：
      该说法**只对 LLM 通道成立**；硅基流动的 rerank/embedding 宽松得多
- [x] D3 明确这是**适用范围修正而非推翻**（24 对 LLM 通道仍有效，只是不能外推）
- [x] D4 指出真正的天花板在**应用侧闸门（24）与 LLM 通道**，不在 embedding/rerank
