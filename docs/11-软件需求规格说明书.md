## 1. 引言

### 1.1 目的与范围

- **范围**：C 端"恋爱军师"产品的用户侧功能，共**四大模块、核心 14 项**。远期差异化能力（沙盘/诊断等）归入 §6 附录，按数据决策立项。
- **不在范围**：B 端机构运营（配额计费/审核后台，ADR-13 冻结）；多租户完备性工程（ADR-13）；实时音视频。
- 本文与代码的对应关系见 §7 可追溯性表；接口字段以 [05-API契约设计](05-API契约设计.md) 与代码注解为准。

### 1.2 术语

| 术语 | 含义 |
| --- | --- |
| sessionId / conversationId | 会话标识（一次对话 = 一个会话） |
| SSE | Server-Sent Events，流式输出协议（打字机效果） |
| RAG | 检索增强生成：从知识库检索相关内容注入回答 |
| Agent | 多步自主任务执行器（现为 LoveManus） |
| Skill | 从优质对话反思萃取的技能卡片（进化模块产物） |
| 话术三级建议 | 安全牌/进击牌/后撤牌三种回复话术及应对预案 |
| 情绪刹车片 | 深夜+极端情绪表达时自动介入的冷静提示机制 |

### 1.3 需求编号规则

`FR-{模块}-{序号}`，模块：`COMM`（会话沟通）/ `CORE`（恋爱辅助）/ `AGENT`（智能体执行）/ `FB`（反馈成长）。

## 2. 总体描述

### 2.1 产品定位与用户特征

**AI 恋爱军师**：基于对话的恋爱关系咨询、约会规划与沟通能力训练。核心用户场景是**连续多轮的情感咨询**——用户带着一段关系、一个当下的情绪问题来聊，AI 需要记得这个人、这段关系、上次的结论（记忆系统，ADR-14），并在敏感内容上守住心理与伦理边界（07）。

### 2.2 运行环境

Java 21 · Spring Boot 3.4.4 · Spring AI 1.1.8；MySQL 8（业务主库）+ PostgreSQL/pgvector（向量检索）+ Redis（缓存/断点）；mcp-server 独立进程（8125，Streamable HTTP）。LLM：LlmGateway 主备（GoPlan 主 / DeepSeek 官方备）+ 视觉 mimo-v2.5（ADR-17）。

### 2.3 四大模块总览

| 会话与沟通 | 认证、会话生命周期、流式聊天（含 RAG/多模态可选能力）、历史管理 |

| 智能体执行 | Agent 复杂任务、任务进度、工具调用可视化 |
| 反馈与成长 | 赞踩反馈、自动技能萃取 |

## 3. 功能需求

### 3.1 会话与沟通模块（8 项）

**FR-COMM-01 注册/登录**
- 描述：用户名注册 + 登录，签发 JWT；`/auth/me` 返回当前身份。
- 状态：✅ 已实现（`/auth/register|login|me`）。
- 验收：注册→登录→me 用户名一致（09 §7.1）；未认证访问受保护接口 401。

**FR-COMM-02 创建新对话**
- 描述：发起新会话自动分配 sessionId，可注册会话归属与标题（`/memory/register`）。
- 状态：✅ 已实现。
- 验收：注册归属后会话出现在个人列表；抢注他人会话 403（09 §7.6）。

**FR-COMM-03 流式聊天**
- 描述：SSE 逐字输出；缺 chatId 返回 400；多模态（`mediaIds`）为可选能力开关（ADR-11）。
- 状态：✅ 已实现（`/Love_app/chat/sse`）。
- 验收：流式文本直至结束无 5xx；缺 chatId 400（09 §7.2）。

**FR-COMM-04 RAG 增强聊天**
- 描述：开启后 AI 检索知识库（父子索引 + 查询改写，ADR-15）辅助回答；属"聊天 + 知识检索能力"，非独立模式。
- 状态：✅ 已实现（`/Love_app/chat/sse/rag`）。
- 验收：回复与恋爱知识领域相关，非答非所问（09 §7.3）。

**FR-COMM-05 历史会话列表**
- 描述：按时间倒序展示本人历史会话（含消息数）。
- 状态：✅ 已实现（`/memory/conversations`）。
- 验收：仅本人会话可见（09 §7.4）。

**FR-COMM-06 对话详情**
- 描述：进入具体会话浏览完整聊天记录（message 表，Phase 2 真源）。
- 状态：✅ 已实现（`/memory/{conversationId}`）。
- 验收：本人可读、他人 403（IDOR，09 §7.6）。

**FR-COMM-07 删除对话**
- 描述：软删除（message.deleted=1，04 §2.2）；注销场景的**硬删除**（级联删向量/Skill）🚧 Phase 3 ADR-5。
- 状态：✅ 软删已实现（`DELETE /memory/{conversationId}`，现状语义=清空该会话历史）；硬删 🚧。
- 验收：删除后列表/详情不可见；重新登录不复活。
- **待讨论**：现状端点语义是"清空历史"（clearHistory）而非"删除对话条目"，与前端交互对齐方式待讨论（05）。

**FR-COMM-08 清空全部历史**
- 描述：一次性清除全部对话记录及相关向量数据（删除权，ADR-5）。
- 状态：🚧 Phase 3（随注销级联删除实现，04 §4 生命周期）。
- 前置：ADR-5（已接受）；与"删除对话"统一为删除权语义。

### 3.2 恋爱辅助核心模块（2 项，均已实现，2026-08-25）

**FR-CORE-01 话术三级建议**
- 描述：针对"对方不回消息""回复冷淡"等场景，生成**安全牌/进击牌/后撤牌**三种话术，并附对方可能反应与应对预案。
- 状态：✅ **已实现（2026-08-25，ADR-18 + phase4-advice）**。实现：关键词路由识别（CapabilityRouter.isAdviceRequest）→ 系统提示词激活段（优先于"先澄清问题"原则）→ SSE `event: advice` 结构化事件（`type/tiers/content/reaction`）→ `advice.request/activated` 指标。
- 业务规则（伦理边界，硬性）：
  1. 建议是**给用户自己的沟通选择**，不是教操控对方——生成内容禁止包含诱导/操纵/贬损对方的指令；
  2. 与 PUA 教学的边界：涉及"拿捏/操控/打压对方"的话术一律不生成（护栏 L3 兜底，07 §5-3；V17 操控意图规则）；
  3. 每套建议附"对方可能反应"时，只描述沟通可能性，不保证结果。
- 验收：三类话术齐全；极端用例（操控意图"怎么PUA她"）被 L3 拦截；触发/采纳观测点已落（`advice.request/activated`，08）。

**FR-CORE-02 情绪刹车片（自动触发）**
- 描述：深夜时段检测到极端情绪表达（分手/你从来/滚 等），自动介入：拦截冲动回复 + 弹出冷静期建议 + 提供转换句式。
- 状态：✅ **已实现（2026-08-25）**。挂 ADR-6 三级梯度（属 L2 降温类，06 §4）。
- 业务规则：
  1. 只对**用户输出**生效（拦截的是用户冲动发言），不改变 AI 回复的共情基调；
  2. 深夜时段判定（`app.emotion-brake.start-hour/end-hour`，默认 23:00–06:00）与极端词清单（V15 `emotion_brake_*` 规则）均可配置；
  3. **误伤控制**：触发必须附冷静期与可选"继续发送"，绝不替用户做决定（信任红线，00 原则三）；
  4. 观测：`emotion_brake.triggered`（08）。
- 验收：深夜+极端词触发；白天同词不触发；触发后可继续发送。

### 3.3 智能体执行模块（3 项，已实现）

**FR-AGENT-01 复杂任务执行**
- 描述：输入复合指令（如"帮我规划周末约会方案"），AI 自动分解任务、调用工具（搜索/天气/图片/PDF 等 10 个工具）、汇总结果。
- 状态：✅ 已实现（`/Love_app/chat/LoveManus`，执行核心 = spring-ai-alibaba ReactAgent，ADR-8；任务落库 ADR-3 + 心跳补偿）。
- 验收：多步执行含工具调用迹象、正常收尾不无限循环；Terminal/File 工具不在白名单（09 §7.5）。

**FR-AGENT-02 任务进度查询**
- 描述：异步任务提交后，前端轮询获取执行状态（RUNNING/SUCCESS/FAILED）。
- 状态：✅ 已实现（`/Love_app/chat/LoveManus/task/{taskId}`）。
- 验收：崩溃恢复场景任务被补偿标记 FAILED、可重提（09 §7.5 / Phase 2 验收）。

**FR-AGENT-03 工具调用可视化**
- 描述：前端展示 Agent 正在调用哪些工具（如"正在搜索餐厅…"）。
- 状态：✅ 已实现（SSE 事件携带工具调用信息；前端展示层随实现完善）。
- 验收：任务执行过程中工具调用步骤可见。

### 3.4 反馈与成长模块（1 项，已实现）

**FR-FB-01 赞踩反馈 + 自动技能萃取**
- 描述：对 AI 每条回复点赞/点踩（`/evolution/vote` + `/memory/message/{id}/feedback`）；数据用于离线反思——优质对话被萃取为 Skill 卡片（ReflectionScheduler 后台），经审核后入库供 RAG 检索。
- 状态：✅ 已实现（数据链路 Phase 1/2；Skill 审核状态前置为 Phase 3 加固项）。
- 验收：投票成功写 knowledge_vote；message.feedback 可写可查（04 §2.2）；萃取产物为脱敏 Skill（07 §5-4）。

## 5. 业务规则与明确不做

### 5.1 非目标（绝对不做，01 §3）

- 不做专业心理治疗/精神科诊断（检测到自伤信号→转介，07 §5-2）；
- 不做教用户操控他人的内容（PUA 类 L3 阻断）；
- 不做通用文件解析（图片是唯一非文本输入，ADR-11）；
- 不做实时语音/视频（近期）；文本+图片+SSE 为交互形态；
- 不做通用聊天机器人（Prompt/RAG/工具全部围绕亲密关系领域）。

### 5.2 立项前提式不做（科学性与合规未证前不做）

以下功能在**科学性与合规边界未确认、真实数据未积累前不进入承诺**（属 §6 远期附录，非绝对不做）：
- 认知诊断、人格诊断报告、关系健康度仪表盘（诊断三件套——前置 ADR-10 定稿 + 合规评审 07 §5；LLM 判定的效度需可论证）；
- 用户成长等级（算法无数据支撑前不做）。

### 5.3 伦理红线（话术三级/情绪刹车片立项时强制执行）

- 建议是给用户的选择，不是操控工具（FR-CORE-01）；
- 情绪介入不替用户做决定，必须可继续/可跳过（FR-CORE-02）；
- 对外发布门槛 = P3 完成（10 L81）。
