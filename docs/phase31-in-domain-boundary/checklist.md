## Q2 ADR-61 那条**未归因**的 −44%：归因完成 → **H1（先答后问）**

| 假设 | 结论 |
|---|---|
| H1 改为**先答后问**（counter-question 扩散到 (A)） | ✅ **成立** |
| H2 变相拒答 | ❌ 不成立 |

**原文证据**（「我和最好的朋友闹翻了」456 字）：

> 先抱一下你🌸…有一点可以先说：朋友之间的修复，跟亲密关系一样，靠的不是一句笼统的"对不起"，而是**具体**。
> **一个能用的道歉结构是**：说出行为 / 说出影响 / 说出改变 ⚠️最关键的一条：**不要有"但是"**…
> **不过要给你真正对症的建议，我还得知道几件事**：1.导火索是什么？…

→ **先交付了一个能立刻用的东西**，**然后**才问细节。这与"变相拒答"方向相反，
且比旧版（一堆通用道理、456→864 字）**更有用**。

📌 所以 ADR-61 §五 第 3 条（G6 864→484 未归因）**关闭**：
**字数下降来自"先给可用的 + 再问"，不是不答。**

## 决策与实施：**选 A**（Mitsuki 拍板）—— 判据书面化，不改处置

→ 决策记录见 `docs/03` **ADR-64**。实现：在 `SCOPE_ANCHORED` 的「判断准则」后追加一段**写死的落点判据**
（人/关系/相处/情绪 → (A)，**不论是否恋爱**；事务/流程/职业/方案 → (B-1) 一句方向 + 转介）。

### 验证：目标是**处置方向零变化**（不是"变好"，也不是"字数不变"）

同装置、同参数前后对照（`GROUPS=G6,G8,G9 REPEAT=3 ARMS=anchored-help`，量具健康全 0）：

| 问题 | 落点 | 改前 → 改后（中位字数） |
|---|---|---|
| 妈干涉婚姻 / 朋友闹翻 / 朋友借钱 / 爸重病 / 室友和女友吵架 / 妹妹被PUA | 人·关系 | 983→1147 / 447→545 / 881→897 / 535→552 / 671→888 / 1109→1367 |
| **同事抢功劳** | **事务** | **171 → 203（仍最短、仍转介）** |
| 男朋友不回消息（基线） | 恋爱核心 | 520 → 427 |

**读法**：① 处置方向零变化 —— 该答的仍答（含"他人关系""间接涉恋爱"）、事务落点仍转介；
② 关系类普遍**略增**（判据明确"非恋爱的人际也算 (A)"）；③「同事抢功劳」这次直接用了 prompt 的
示例句「这超出了我的专长范围哦」，于是被分类器标成 `refusal_long` —— **它本来就是该转介的那条**；
④ 恋爱基线 −93 字属 **n=3 单臂的轮间噪声**，不当效应。

回归：单测 **367/367** · E2E **22/22** · A3 自报仍为 `anchored-help`。

### ⭐ 实施中踩到的坑（已进 ADR-64 §限制 4 与 `docs/11`）

改完 `SCOPE_ANCHORED` 后一条断言**报红**，但用编译产物**单独比对却 `equal=true`**。
根因：**`SYSTEM_PROMPT` 是编译期常量 → 被内联进引用它的类**；Maven 增量编译留下**旧内联副本**
→ 断言对着**旧 prompt 文本**跑。
处置：删 `target/{classes,test-classes}/**/*.class`（**不要 `mvn clean`**，会删 `application-local.yml`）后全量重编 → 全绿。
⛔ 含义：**本仓频繁改提示词，"红/绿"都可能是在对旧文本判** —— 改提示词后必须确认"跑的是新文本"。
