> 结论见 `spec.md`。**结构性修复确凿；既有 45 例上质量指标无可见提升，我原来的理由被实测否定。**

## A. 前置验证（决定方案的那一步）

- [x] A1 知识块 metadata 的真实结构已实测：**439 条里 `metadata->>'source'` 全为 NULL**（根本没有这个键）
- [x] A2 记忆块 461 条：`source='memory'`
- [x] A3 确认风险为真：`metadata->>'source' != 'memory'` 对知识块求值为 **NULL** → WHERE 里算 false
      → **会把知识块一起滤光**（这正是选 COALESCE 白名单式排除、而非裸黑名单的原因）
- [x] A4 方案选型记录在案（A 补字段 / B 原生 SQL 下推 → 选 B：零数据迁移 + 真下推 + 与既有 `keywordSearch` 同风格）
- [x] A5 **修正计划时的一个错误假设**：原计划只改向量通道，实测发现**关键词通道同样混入记忆** ——
      「沟通」95/174 = 55%、「冷战」21/52 = 40%、「吵架」18/65 = 28% → 两条通道都下推
      （原清单 F3 的猜测"关键词按 content LIKE 匹配、理论上不会命中记忆"**是错的**）
